## 2. 新增：登录与身份

- 首次访问 → 单字段页：粘 token（说明可从 `tidewatch token --show` 或 `data/auth-token.txt` 取）；
- 登录成功 → HttpOnly cookie，7 天滚动；顶栏显示"服务地址 + 退出"；
- 未认证访问任何页面 → 302 到登录页（API 侧 401），**不泄露任何任务/路径信息**；
- 会话过期时 UI 显示就地重新登录弹层，不丢当前页面上下文。

## 3. 新增：移动端响应式（LAN 访问的直接后果）

| 断点 | 布局 |
|---|---|
| ≥1280 | 原桌面布局（侧栏 + 内容区 + 详情抽屉） |
| 768–1279 | 侧栏折叠为图标条 |
| <768 | 单列 + 底部 Tab（总览/录制/设置）；卡片改紧凑行；详情全屏覆盖 |

移动端优先保证四条高频动作**单手可达**：看某任务在不在播、看今天录了几场、
停止这一场、播某场产物。低频配置（Cookie、插件、诊断）允许在移动端只读或折叠。

## 4. 新增：推送渠道设置

设置页新增「通知」分组：
- 渠道列表：ntfy / Bark / Telegram / SMTP / Web Push（逐项开关 + 配置 + **发送测试消息**）；
- 每个渠道显示最近一次投递结果与失败原因（失败不能静默，与"沉默型缺陷"同一纪律）;
- 铃铛保留：未读数、列表、全部已读；点击按 kind 指路（needs_auth → Cookie 分组、有会话 → 录制页那一场）。

## 5. 可选增强：PWA（明确限制）

`http://<LAN-IP>:8686` **不是 secure context**：装不成应用、收不到 Web Push、无 service worker。
- 若用户用 Tailscale Serve / Caddy 反代拿到 HTTPS：manifest + SW 即生效，可"安装"到 Dock/主屏，
  Web Push 渠道可用（需 VAPID 密钥，服务端生成）；
- 默认不以此为主线，文档里作为"想要更好体验的人自己加"。
- 注意：manifest 的 `start_url` 用相对路径，避免换端口/换域名后失效。

## 6. 录制页时间线（保留 v1 的核心增量）

段色块 + 红纹缺口段 + 重连竖线标注；hover 出参数指纹，点击缺口展开成因（stderr 分类结果）；
`origin=cap/new` 用连接线表达"承接上一场"。数据源：`segments` 表 + `recording.gap` 事件，
API 已齐全，零后端改动。移动端退化为纵向条形列表（横轴时间不可读时改为"按段列时间"）。
